## 顶层决策

| #   | 决策                                                                  | 理由                                                                              |
| --- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| D5  | 拓扑只有 full mesh，10 个 orca node 上限                              | 10 个 orca node = 45 条链路，自适应心跳下总流量约 10 req/s，完全可控；ring 解决的是不存在的问题 |
| D6  | 无 epoch、无 incarnation、无全局成员表                                | 成员状态是每个 orca node 的本地观测；引入版本号就需要共识，而这里不需要共识       |
| D20 | 集群逻辑只放插件，不改 DSH 核心                                       | 内核保持单机语义；集群是可选扩展                                                  |
| D30 | 10 个 orca node 是建议上限，不是硬限制；超过时没有检查，见 [§11](11-open-questions.md#11-未决问题) | 心跳节奏随成员数自适应（`N` 秒，夹在 2–10s），总流量线性增长；超过 10 个时判定延迟变长，不是静默失败 |
| D37 | `src/` 按限界上下文分目录、依赖只能向下（[§9.1](09-implementation.md#91-单包内的模块划分)），由 `test/architecture.test.ts` 固化；保持纯 DI，不引入 DI 容器（[§9.6](09-implementation.md#96-工程约定)） | 服务对象早已存在（`createX(deps)` 工厂、唯一装配根、无环），缺的是边界：目录 + `index.ts` + 架构测试把边界变成可检查的约束。容器只会带来字符串 key 与隐式生命周期，装饰器与运行时反射和 `erasableSyntaxOnly` 冲突，插件侧已经跑在 Cordis 这个容器里 |
