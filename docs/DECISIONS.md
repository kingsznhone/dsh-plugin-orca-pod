| D40 | DSH 公开导出的类型、常量与工具一律直接用，不在本包重抄、手写或套别名：运行时依赖 DSH 包（清单见 `package.json` 的 `dependencies`）；模型选择的线上形状就是 DSH 的 `ModelSelection` | 手写的副本会和宿主漂移（`PermissionMode` 与 `SandboxMode`、effort 清单、凭据名语法、摘要截断长度都出过这种情况），而且掩盖了宿主已有的保证（类型化返回值被重新解析）。这些包大多不依赖 cordis，独立 CLI 同样能加载 |
| D41 | `src/` 按功能重组为 8 个上下文 `core ← {mesh, executor} ← task ← api ← node ← {cli, plugin}`（同层互不引用，仅类型的环也算违规）；服务对象用 class，协作者走构造器参数属性，私有协作者由拥有者 `new`，共享对象由创建者传入，子系统间通知用各自的 `readonly events`；不做依赖注入（无容器、`XDeps`、端口接口、Provider），只有多实现时才设接口；关闭 `erasableSyntaxOnly`，`src/` 不再由裸 node 运行（脚本走 `tsx`，harness 跑 `lib/`），`enum` / `namespace` 由 Biome 禁止；测试使用真实对象，设计不为测试让步（`refactor.md`，修订 D37） | 闭包工厂的状态与方法混在一个作用域里（`createWorkgroup` 345 行），接口类型与实现要写两遍，组合根靠声明提升解开循环；按技术层横切的目录让一个功能（组网）散在 5 个目录。参数属性省掉 class 最主要的样板，代价只是不能再裸跑 `src/`，而这并没有换来别的简化。行为差异两条：approval broker 的 listener 异常改为被吞掉（与 tracker 一致），但会经 `NodeLogger` 记一条 warning；工作区目录的创建与首次测量挪到 `start()`。与方案的出入两处（第三处，`TaskRecord` 并进 `task/runner.ts`，已由 D42 撤回）：“取成员发布的文件”抽成 `mesh/BlobFetcher`，让 `api` 不必认识 `OrcaNode`；`DEFAULT_PORT` 留在 `core/constants.ts`，因为面板前端要读它，而 `core/net.ts` 依赖 `node:net` |
| D42 | 模块级函数的去留按固定规则判定（`refactor.md` §2）：只有一个调用点且不超过三行、或只是给表达式起名的内联（R1）；参数里带着某个 class 的状态或协作者的，成为那个 class 的方法，导出的也一样（R3）；一个类型加一组以它为参数的函数收成 class（R4）；未导出且只在一个 class 里用的，成为它的 `private` 方法，不读 `this` 的写成 `private static`（R2）；只有被 ≥ 2 个模块用的无状态纯计算、导出后有独立单元测试的纯契约、CLI 子命令的一次性过程保持为函数（R5）。只为测试存在的公开面（公开方法与字段、返回计数、选项字段、`Pick` / 结构参数类型、依赖袋）一律删除或改私有，测试改走真实入口（R7）；一个默认值、一个检查、一个派生值只在拥有者那里算一次（R9）；不用 `ReturnType` 给已有类型换写法，不用 `X & { 偷带字段 }` 把参数塞进另一个配置对象（R10）。修订 D41：`TaskRecord` 不再认识 runner，回到 `task/record.ts` | 第一轮只换了外壳：自由函数其实是某个 class 的方法（`plugin/catalog.ts` 的六个函数都把 `logger` 当参数传）、数据袋加一组操作它的函数（`PeerRecord`、`WorkspacePaths`）、封装被打开（runner 为同文件的记录公开 8 个字段）、转发与包装（`self()` 两跳转发、只有测试订阅的 `ChangeSignal`）、同一件事算好几遍（任务时限默认值三处、“节点没在运行”四处、`busy` 两个来源）。行为差异：多段文字的消息在 CLI 与 tracker 通知里改为换行分隔；notes 目录只列常规文件，面板与任务书一致；面板不再有变化推送入口（本来就靠轮询）；“节点没在运行”的报错在启动失败后带上失败原因 |
| D43 | 插件侧的状态是判别联合：`Pod`（原先按机制命名）的 `PodStatus` 为 `unconfigured / starting / running / failed / stopped`，一次运行是 `PodRun = { node, port }`，整个换、不改；`Pod` 之外读取当前运行只有四种写法——展示读 `pod.run`、动作先 `await pod.settled()` 再 `requireRun()`、后台没有就跳过、写副作用不依赖“碰巧有节点”（`refactor.md` H1、H2）。每个事实只有一个所有者、一条路径：配置只经 `commit()` 落地并重启，模型目录只经 `Pod.advertise` 装到节点，待审批只在 `ApprovalBroker`，派发的会话与派发记录同时写入；所有者之间的引用单向（H3）。必须先做 X 再做 Y 的地方由一个方法按顺序做完（H4）。class 名是领域名词：`Pod`、`PanelModel`、`PanelRoutes`、`PodBundle`，面板契约全在 `panel-api.ts`（H5）；构造只组装，`apply` 是 `new PodBundle` → `attach` → `start` 三段（H6）。修订 D41、D42 | 前两轮之后每个 class 单独读都干净，整体仍不符合直觉：“插件有一个节点”在代码里是“一个槽位里时有时无一个节点，每次重启都换”，这个差别没进类型，17 处读取各用一种空值策略（返回空、静默跳过、抛错、先等再抛错），其中静默跳过让派发记录丢了会话；一个状态拆成 7 个可空字段，原地重启时 `ready` 早已 resolve 而节点正在重启，工具报“没在运行”；同一件事两条路径（模型目录装到节点有两条路、待审批有两个来源，批准后卡片以 `agent_id: null` 重现）；顺序只写在注释里（`reconfigure` 的后半段取决于宿主机制）；名字说机制不说是什么，插件入口 `new` 出来只为副作用。行为差异：原地重启期间的工具调用、批准与拒绝、面板的取消 / 详情 / 下载会等重启结束，不再立即报错，报错按状态区分；每次启动成功后重新读一次宿主模型目录；批准或拒绝后卡片立即消失；派发记录的 `agent_id` 在条目创建时写入；已放弃的任务 id 对任何入口都不再被接手；插件配置里没有 `peers` 键、继承层里有时，`disconnect` 的空写入由“不重启”变为“原地重启” |
| D44 | 第四轮重构（`refactor.md` 的 M1–M5）：**mesh 是一张节点表，节点是对象**——`Mesh` 持有 `Map<节点 id, OrcaNode>`，本机自己也在表里，只用 `id === selfId` 判断，不拆 Local/Remote 两个类；要用哪个节点就先 `mesh.resolve(ref)`（id、唯一显示名或 URL）再调它的方法；一个节点的状态只在它自己身上；共享的东西按资源只有一份、按 orca 实例划作用域（一个 data_root 一个 `SqliteDb`、一个实例一个 `MeshContext`），**不用模块级全局变量**。分层放宽为 `core ← executor ← task ← mesh ← api ← node ← plugin`（派发是“对一个节点做的事”）。**线协议不兼容**：join 与心跳合并为 `hello`；每个节点间请求在头里同时带 Ed25519 签名与 workgroup HMAC 证明，成员表不再管准入（改了密码的节点在下一个请求就被拒），答复由应答方签名并绑定请求 nonce；文件下载的答复签名覆盖 status 与 `blob_id`，字节按 sha256 校验。**机密只在 DSH 凭据库，派生物只在内存**：密码是引用 `ORCA_POD_PASSWORD`，节点私钥（base58 种子）是记录 `orca-pod/node`，workgroup key 不落盘。**只保留 DSH 插件形态**：删除独立运行、`orca-pod install` 与整个 CLI；任务里的文件改由执行器交接（`inbox/` 取、`outbox/` 发布，`send` 的 `files` 与工具 `fetch`）。**一台机器一个节点，所有 profile 共用**：`data_root` 固定为 `$DSH_HOME/orca-pod`，设置改存 `settings.json`（推翻 D43 K2“设置就是插件配置”），`reset` 删除整台机器的节点、无分支；端口即锁，`Orca.start()` 第一步绑定端口，之后才打开数据库、恢复任务 | 节点的状态曾散在五个类里、调用方拿 URL 寻址、自己不在表里要在六处拼 `[...list(), self]`；join 与心跳是同一个握手却写了两遍还要靠“被拒就补 join”修补；准入只在请求体里证明，答复没有签名；机密落在 DSH 凭据库之外；CLI 只剩取文件和发布文件两个用途，改由执行器代办后独立运行形态可以整体删除 |
| D45 | **tracker 与会话无关，派发日志的读写分开**：`send` 只往派发日志新增条目，之后条目的状态只由 tracker 写（每次变化一条 `UPDATE`，用 `json_patch`，只改未结束、且确有变化的条目），`status`、面板与审批的读取都不写日志。tracker 每轮的工作集就是派发日志里未结束的条目，插件启动即开始轮询，不按会话恢复跟踪（删去 `agent/created` 钩子与 `Tracker.track` / `restore` / `forget`）；会话只在交付 notice 时按 `agent_id` 向宿主注册表查，找不到就不通知。读不到的任务（404、节点已不在节点表、401/403、连续 5 次没有响应或 5xx）由 origin 记成 `failed` 并停止轮询，推翻 [§8.2](08-reliability.md#82-orca-node-失联任务不重发读不到就记失败) 原先“origin 不替它判死，只说跟踪中断”的做法 | 原先 tracker 的工作集是内存里绑着 `Agent` 对象的表，只能跟踪宿主里活着的会话：重启后要等会话被创建才接上，会话被卸载就停止轮询，日志一直停在未结束；读路径顺手刷新日志，写入方散在几处。“放弃跟踪”只存在内存里，下次启动又会被拉起，而一个永远未结束的派发既占轮询、也让 agent 等不到结论 |
| D46 | **文件不是任务的一部分，blob 自成一体**：任务模型里没有文件字段（删去 `metadata.pod.files`、`TaskView.artifacts`、inbox 暂存与 outbox 发布、`input_unavailable`、echo 脚本的 `artifacts`）；交接靠文本，发布方把 `<节点 id>/<sha256>` 写进任务文本或结论，需要的一方用 `orca_pod fetch` 取。`publish` 把文件**复制**进 `<data_root>/blobs/`，过期时副本与映射一起清扫（启动时与每小时）。**任务在宿主自己的 profile 里运行**（D60 已推翻此段：改为固定 `acp` profile；`ctx.profileContext.name`，删去 `acp.profile`），所以任务进程里也有本插件：见到 `ORCA_POD_IN_TASK=1` 不起节点，只注册 `fetch` / `publish` 两个方法的 `orca_pod`，经本机节点的本地路由（`local` 访问级别，执行器注入的 `ORCA_POD_NODE_URL` 与每次启动随机生成的 `ORCA_POD_NODE_TOKEN`）办事。推翻 D44 里“任务里的文件改由执行器交接（`inbox/` 取、`outbox/` 发布）”一句 | 执行器代办文件让 task 的线上形状、状态机、任务书、工作区与错误码都知道 blob；而任务 agent 一旦有工具可用，文件就只是“谁发布、谁来拉”。不引入 MCP（用户决定），也不另配 profile：用宿主的 profile 是让任务进程拿到这个工具的最短路径，代价是任务会话带着宿主 profile 的其他插件与设置。原地登记的文件会被后来的改动破坏、也从不清理，复制后 TTL 才真正归 blob 管 |
| D47 | **生产代码只留生产在用的东西**：只给测试用的实现、选项与公开面一律删掉，测试从真实入口走。删去 Memory 版的任务、派发、blob 与凭据存储和 `persistent` 开关（节点总用 `<data_root>/tasks.db`，测试用临时目录上的真 SQLite，宿主凭据库在测试里用内存替身）；只剩一个实现的存储接口随之消失，任务表、派发表与 blob 映射由各自的所有者直接持有（`JsonTable`）；`TrackerOptions` 的时间旋钮改为模块常量（测试用假时钟）；只被测试调用的方法改私有或删除，只在本文件用的导出去掉 `export`。节点表的规则同样从真实入口测：`test/support/net.ts` 是进程内的工作组（每个节点是真 mesh 加真 gateway，出站调用交给目标 gateway 的 Fastify `inject`，时间由假计时器推进，测试决定哪两点之间不通），`Mesh` 的 `evaluate` / `mergeRemote` / `directory` 与 `OrcaNode.dialOrder` 因此收为私有。保留模块边界上整块替换的注入点（`OrcaNodeOptions` 的 `executor` / `clock` / `timings` / `fetch`）与 `Gateway.app`（Fastify 的 `inject` 走完整的 HTTP 入口，测试借它模拟来源地址） | 为测试留下的局部切片让模块多出第二种形态：Memory 存储与 SQLite 存储可以行为不一，测试测的是前者、跑的是后者；测试专用的选项与 getter 让内部状态成了公开契约，改实现就得改接口 |
